采用候选图建模与冲突驱动的布尔约束求解，恢复满足度数和几何限制的任意一组栅栏布局。程序以 C99 实现，报告依据逐例测试记录编写。

Chapter 1 问题描述

1.1 任务与输入输出

花园是 n 行 m 列的网格，2≤n,m≤50。非零格点放置度数为 1 至 4 的连接器，零格点表示没有连接器。栅栏必须水平或竖直，不能自行转弯，也不能在没有连接器的位置相交。本项目根据连接器位置和度数恢复布局；无法满足约束时输出 No Solution。

每个连接器需要输出所在行、列及上、下、左、右四个方向的 0/1 状态，采用从 1 开始的行列编号，按行优先排序。多解时输出任意合法布局，不要求与样例逐字相同。题目没有要求所有连接器构成一个连通分量，也没有最小化总长度的目标。

1.2 问题中的两类约束

度数约束只规定连接器使用多少个方向，不能单独保证几何合法。例如 3×3 花园四条边中点各有一个一度连接器、中心为空时，水平和竖直两条线都被迫选取，虽然端点度数均满足，却在中心交叉，因此仍应判为无解。

程序将“恰好满足度数”与“空位置不交叉”分别编码。连接器处允许多个方向相接，包括四路交汇。没有连接器的花园对应空布局，标准输出为空；输入格式错误与合法输入无解分开处理，前者写入标准错误并以非零状态退出。

Chapter 2 数据结构与算法

2.1 候选边的完备构造

沿每一行和每一列扫描，仅连接相邻的非零格点，得到候选图 G=(V,E)。若一条直线经过另一个连接器，它可以在该连接器处分成两条候选边；因此无需添加跨越中间连接器的跳跃边。每个连接器至多关联四条候选边。

令 xe∈{0,1} 表示候选边 e∈E 是否被选取。内部文字编码采用 2*e 表示 xe，2*e+1 表示 ¬xe。端点、端口方向和经过的空格在建模阶段确定。记顶点 v 的关联边集合为 δ(v)，可用方向数为 dv=|δ(v)|，目标度数为 kv。

数据结构内容及用途
Garden行列数及每个格点要求的度数
Model.edges候选边的两个端点和正向端口
Model.incident每个连接器四个方向对应的边编号，无边为 -1
horizontal / vertical各空格经过的水平、竖直候选边，用于发现交叉
Clause / watches子句文字数组及按文字编号组织的双监视表

trail / limits赋值轨迹及各决策层起点，支持撤销赋值
activity / heap变量活动度与最大堆，只改变搜索顺序

2.2 度数、交叉与必要条件

每个连接器恰好选择 kv 条关联边，即

∑e∈δ(v)xe=kv,v∈V.

当 kv>dv 时加入空子句。否则，先对任意 kv+1 条关联边规定“不能全真”，得到至多 kv 条的条件：

⋀A⊆δ(v)|A|=kv+1(⋁e∈A¬xe).

再对任意 dv−kv+1 条关联边规定“不能全假”，得到至少 kv 条的条件：

⋀B⊆δ(v)|B|=dv−kv+1(⋁e∈Bxe).

两组条件合起来等价于精确度数约束。由于 dv≤4，至多枚举 2dv≤16 个子集，每个连接器最多产生 8 个子句。

若空格同时经过水平候选边 eh 与竖直候选边 ev，则要求

xeh+xev≤1⟺¬xeh∨¬xev.

同一空格每个轴至多存在一条候选边，因此扫描空格即可发现全部交叉。

此外，每个候选图连通分量 C 都必须满足

∑v∈Ckv≡0(mod2).

若分量能够二染色，记其两侧为 AC、BC，每条选中边对两侧各贡献 1，故还必须满足

∑v∈ACkv=∑v∈BCkv.

这些必要条件只用于提前判定矛盾，并未假定候选图总是二分图。测试中的五连接器矩形布局，在一条边上插入一个连接器后便形成可解的奇环。

2.3 建模伪代码

以下采用 Python 风格伪代码表示集合和循环，实际评测程序由 C99 实现。

Python 风格伪代码
def build_formula(garden):
    edges = scan_consecutive_connectors(garden)
    solver = create_solver(len(edges))
    for component in candidate_components(edges):
        add_component_checks(solver, component)
    for vertex in connectors(garden):
        S, k = incident_edges(vertex), degree(vertex)
        if k > len(S):
            add_clause(solver, [])  # 空子句表示矛盾
        else:
            for A in subsets(S, size=k + 1):
                add_clause(solver, [NOT(e) for e in A])
            for B in subsets(S, size=len(S) - k + 1):
                add_clause(solver, [e for e in B])
    for h, v in empty_cell_crossings(edges):
        add_clause(solver, [NOT(h), NOT(v)])
    return solver

2.4 约束求解

求解器使用冲突驱动子句学习（CDCL）。赋值后只检查刚刚变假的文字所在监视表。若子句能找到另一个非假的文字，就迁移监视；否则剩余监视文字必须被推导为真，或形成冲突。单位条件保存在赋值队列中，空子句立即表示矛盾。

冲突发生后，沿赋值轨迹反向分析原因子句，并消解到学习子句中只剩一个当前层文字，即 First UIP。回跳到学习子句其他文字的最高层后，新的子句会立刻推导一个赋值。变量活动度增加，使近期冲突涉及的变量优先被选择；堆的比较规则相同时优先较小编号，保证运行可复现。

重启在冲突预算达到阈值后执行，保留学习子句和已保存的分支相位。初始预算为 100，此后按 1.5 倍增长，达到上限附近后停止增长。当前版本不清理学习子句。所有内存分配均检查失败；运行资源错误不能被当作无解。

Python 风格伪代码
def solve(formula):
    enqueue_original_units(level=0)
    while True:
        conflict = propagate()
        if conflict is not None:
            if current_level() == 0:
                return UNSAT
            learned = first_uip(conflict)
            target = highest_other_level(learned)
            cancel_until(target)
            store_clause(learned)
            enqueue(learned[0], reason=learned)
        else:
            if restart_budget_reached():
                cancel_until(0)
            if all_variables_assigned():
                return SAT
            variable = choose_by_activity()
            begin_level()
            enqueue(saved_phase(variable), reason=None)

2.5 正确性说明

必要性：任意合法栅栏都可分解为同一行或列相邻连接器之间的边，故对应候选边的一个赋值。每个连接器恰好使用 kv 个方向，满足基数子句；没有空位置交叉，满足所有交叉互斥子句。分量必要条件由边对端点度数的贡献直接得到，不会排除合法布局。

充分性：任意满足公式的赋值都在每个连接器上选出恰好 kv 条边。候选边是端点之间没有其他连接器的直线，故没有悬空终点或无连接器转弯。互斥子句排除了所有内部空格上的水平、竖直交叉。将每条选中边同时写入两个端点的相反方向，便得到合法且互反一致的输出。

搜索层面，单位传播只采用子句的逻辑蕴含，学习子句由冲突原因消解产生，不改变原公式的满足模型。回溯撤销赋值而不撤销约束；第 0 层出现矛盾时可判无解。双监视机制保证不会在存在全假子句时返回完整模型。算法思想参考文献 [1]，C 程序未调用外部 SAT 库。

Chapter 4 复杂度与讨论

4.1 建模复杂度

记连接器数为 Nv=|V|，候选边数为 Ne=|E|，空格交叉点数为 Nq。一行至多有 m−1 条水平候选边，一列至多有 n−1 条竖直候选边，因此

Ne≤n(m−1)+m(n−1)=2nm−n−m.

在题目上界 n=m=50 时，进一步得到

Ne≤2×50×50−50−50=4900.

逐行、逐列扫描均为 O(nm)。同一行水平边的内部区间互不重叠，同一列竖直边同理；故登记经过的空格总共只需 O(nm)，不需要对每条边重新扫描整个花园。分量遍历耗时 O(Nv+Ne)。

每个连接器至多产生 8 个长度不超过 4 的度数子句；每个空格至多产生一个交叉子句，且 Nq≤nm。记因分量必要条件不满足而加入的空子句数为 Nbad，则初始子句数和文字总数分别满足

Nclause,0≤8Nv+Nq+Nbad,L0≤32Nv+2Nq.

因为 Nbad≤Nv≤nm，且每个候选边的两个端点共占用关联表中的两个方向，所以 Ne=O(nm)。代入扫描、分量检查及子句生成的工作量，得到

Tbuild=O(nm+Nv+Ne+L0)=O(nm),Sinitial=O(nm+Ne+L0)=O(nm).

程序按上限 50 分配格点数组，固定上限下占用有界；若将行列上限作为参数，其规模随网格面积线性增长。

4.2 搜索复杂度与内存

布尔搜索没有多项式最坏时间保证。候选边构成 Ne 个布尔变量，直接枚举的赋值总数为

Nassignment=2Ne.

活动度、学习和重启可以减少重复冲突，但不能将所有合法尺寸输入都视为同等难度。本实现不承诺对任意 50×50 输入在固定时限内结束。

为描述实际搜索工作量，使用下列记号：

记号含义
Np累计处理的赋值队列项数
Nb分支次数
Nu撤销赋值后重新入堆的变量次数
Nc冲突分析次数
Lmax搜索期间保留子句的最大文字总数，包含学习子句

单次处理赋值的监视扫描最坏检查 O(Lmax) 个文字；堆更新为 O(log⁡(Ne+1))。一次冲突分析至多处理 Ne 个变量及其相关原因子句，还可能对这些变量更新堆。因此，一个按累计操作数表示的保守上界为

Tsolve=O(NpLmax+(Ne+Nb+Nu)log⁡(Ne+1)+Nc[Lmax+Nelog⁡(Ne+1)]).

这里使用 log⁡(Ne+1) 处理空变量集合的边界；空公式的求解额外开销为常数。该表达式刻画实际搜索工作，不构成多项式最坏上界，因为搜索次数和学习子句数量均可能显著增长。

模型、赋值数组、堆和轨迹占用 O(nm+Ne)；子句文字和监视项占用 O(Lmax)。相加得到

Stotal=O(nm+Ne+Lmax).

当前版本不清理学习子句，Lmax 可能随困难实例增长，故不能将搜索全过程内存仍写成初始公式的线性规模 O(nm)。

4.3 实测现象与限制

本次最大尺寸 50×50 的已知可解布局全部恢复成功，并检查了最大 4,900 条候选边的输入。稀疏输入、长边和空格交叉由专项及小规模穷举覆盖；奇环用例验证了没有错误地将任意候选图当作二分图。

无解判定必须同时考虑度数和几何条件。四个一度端点的十字交叉用例即使忽略交叉限制也能满足度数，但实际无解；四路连接器处则允许交汇。输出校验器分别处理这两种情形。

测试覆盖不能代替完整输入空间的证明。大规模试验主要采用已知合法布局反推输入，尚未穷举所有大规模不可满足布局。程序不设置“搜索超时就输出无解”的规则；测试驱动中的超时会作为测试失败抛出。题面未设置 Bonus，本报告不另行虚构扩展评分项。
